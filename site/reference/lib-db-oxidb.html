db/oxidb

Imported as import "db/oxidb" as oxidb, its names are then oxidb.…. Every signature below is the one the checker infers.

A client for OxiDB's document engine, written in Rill.

The wire is the server's native one and the payload is binary: oxiwire.rill does the framing and the tags, shared with the time-series client. What is here is the document surface — collections, queries, the shapes each command answers with.

It spoke JSON until the two were measured against each other. Binary is not the smaller of the two — a reply of six hundred documents came to about a third more bytes, fixed-width numbers being what they are — but it is faster: roughly two and a half times, on a local socket, against the JSON parser as it then stood.

That last clause matters. Most of the gap was the parser rather than the format, and the parser has since been fixed — it took strings a byte at a time, which cost a string the square of its length. Measured again afterwards the binary is about 1.4 times faster rather than 2.5. It is still the faster wire and there is no reason to go back, but the honest figure is the smaller one, and over a slow enough link the extra bytes would take even that back.

Every call answers Ok(data) or Err(message). On this wire the status byte carries which of the two it is, so there is no {"ok":.., "data":..} envelope to unwrap. The connection is a plain socket, so a strand waiting on a reply parks and costs nothing.

fn hello(fd: Int) -> Result(Json, Str)

The handshake, and the one command whose reply is not on the wire the request was written in: the server answers hello before it has looked at the format, so what comes back is JSON whatever went out, and it is the server's own shape rather than the usual envelope — {"ok":true, "server":{...}}. So this reads either, and hands back what the reply says about the server.

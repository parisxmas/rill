db/oxisql

Imported as import "db/oxisql" as oxisql, its names are then oxisql.…. Every signature below is the one the checker infers.

A client for OxiDB's SQL engine, written in Rill.

The wire is oxiwire.rill, the same binary one the document and time-series clients use — the engine is chosen by a field in the request rather than by a port, so one connection could speak to all three. This engine is off unless the server was started with OXIDB_SQL, and it is gated at the write role: there is no read-only SQL in this version.

One request may carry more than one statement, so the answer is always a list of results, one per statement, and each is one of three shapes:

{"ddl": true} CREATE, DROP, ALTER {"affected": 2} INSERT, UPDATE, DELETE {"columns": [..], "types": [..], "rows": [[..]]} SELECT

A row is a list of values positionally matching columns, so reading one by name means finding the column first — sql_at below does that once per result rather than once per row.

One result per statement sent.

fn sql_first(answer: Json) -> Json

The common case is one statement, and a caller that sent one should not have to say so twice.

fn sql_columns(result: Json) -> List(Str)

fn sql_types(result: Json) -> List(Str)

A column's declared type — INT, TEXT, DOUBLE — or the empty string where the engine had none to give, as for a bare NULL in a select list.

fn sql_rows(result: Json) -> List(Json)

fn sql_affected(result: Json) -> Int

fn sql_is_ddl(result: Json) -> Bool

fn sql_at(result: Json, name: Str) -> Int

Where a named column sits in every row of this result, or -1. Worth holding on to across a loop rather than asking per row.

fn column_index(names: List('a), name: 'a, i: Int) -> Int # where 'a is a value type

fn sql_cell(row: Json, i: Int) -> Json

fn sql_value(result: Json, row: Json, name: Str) -> Json

The value of a named column in one row. Fine for a handful; for a table use sql_at once and sql_cell per row.

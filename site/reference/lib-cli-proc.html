Standard library · The command line

cli/proc

Imported as import "cli/proc" as proc, its names are then proc.…. Every signature below is the one the checker infers.

Running another program: a command line handed to the shell, its output collected, its exit status read.

import "cli/proc" as proc
match proc.run("git rev-parse HEAD")
  Ok(r) -> println(r.out)                 # r.status is the exit code
  Err(why) -> println(why)
proc.output("date -u")?                   # the output, or an Err with the status
proc.run(proc.command("grep", Cons("-n", Cons(pattern, Cons(file, Nil)))))
proc.shell("make")                        # output to ours; the exit code

run and output read the child's standard output; its standard error goes where ours goes. command builds a line from a program and its arguments with each one quoted for the shell, so a file name with a space or a $ in it arrives as one argument and nothing more. The calls that wait are declared blocking, so other strands run while a child does.

Functions

fn run(cmd: Str) -> Result(Result_, Str)

The exit code and what the command wrote. An Err is a command that could not be started at all; a command that ran and failed is an Ok with a status that is not zero — it is the caller's to decide what a failure means, and the output is often the reason.

fn output(cmd: Str) -> Result(Str, Str)

The output of a command that succeeded, or the status it failed with, with what it wrote — a one-line answer for the common case.

fn shell(cmd: Str) -> Int

Runs the command with our standard output and error, and gives its exit code; -1 when the shell could not be run.

fn command(prog: Str, args: List(Str)) -> Str

A program and its arguments as one shell line, each argument quoted.

fn quote(arg: Str) -> Str

An argument the shell will pass through unchanged: in single quotes, with a single quote inside written as '\''. A word of plain characters is left as it is.
